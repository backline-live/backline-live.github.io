Adding your own things

  • A scene or effect: a COMP in /project1/scenes (or effects) with an out1 TOP. Give it a custom page with the pars you want to play; set each par's normMin / normMax = the slider range. Read them inside with parent().par.Name or a Parameter CHOP. It appears in the page; its pars are Core targets for MIDI.
  • A par on a knob without mapping (focus knobs): map a controller knob ONCE to av.focus.1 (.2 ...; LIGHTS: lights.focus.1 ...). Knob k then plays the k-th par of the scene on preview. To choose WHICH pars land on the knobs: put them on a custom page named Knobs (in the order you want), they come first; then the other pages in order; pages named Setup... never. A new par on the scene = on the next free knob at once. Switch what the knobs play: av.focus.program / av.focus.preview / av.focus.effect (map them to buttons), or click a scene / effect tile (LIGHTS: a look in the matrix). After a switch a knob does nothing until it reaches the new value (no jumps). A knob you mapped by Learn on the same control wins. Details: MIDI.md §1b.
  • A panel: a COMP in /project1/modules (or tagged avmodule): out1 = its preview, custom pars = controls, pars Azimuth / Elevation / Distance = mouse orbit in the preview.
  • Your own network, controllable (no code): see "Make your own network controllable" below.
  • A light look: start from a template (drag demo/demo.tox in: it adds to /project1/looks warm, cool, chase, pixelmap, figure8, combine, fixtures, example, and to /project1/lightfx strobe, colorize), or make a COMP in /project1/looks with an out1 CHOP: channels <group>:<attr> (bars:dimmer, wash:r), one fixture <group>:<i>:<attr>, a pixel cell <group>:<i>:<c>:<attr>; group _ = whatever row of the matrix it is played on (_:dimmer). Its custom pars are MIDI targets (lights.par.look.<look>.<Par>). A light effect = a COMP in /project1/lightfx (CHOP in -> CHOP out). Details: LIGHTS.md §13, docs/DESIGN.md §2.
  • A fixture type: Setup › Rig › Library → + New type / Import GDTF… (LIGHTS.md §2-3); patching: "Set up the rig" above.
  • A MIDI link: MIDI window → Learn, Learn from TD (change the par in TD, move a control), Map last on PERFORM, or a row in <show>/midi/<id>/av_map.tsv (MIDI.md §1).
  • A controller, a part, a page command: recipes in dev/COOKBOOK.md.

Make your own network controllable

Any of your own TD networks can get faders, buttons and MIDI, without Python:

  1. Drag templates/corepars_template.tox into your project (next to core, or inside a folder up to 3 levels below it) and rename it, e.g. my_look. Read its README DAT.
  2. Its custom page Controls = what you will play. Add your own pars there (right-click the COMP ▸ Customize Component): a Float or Int with a sensible slider range (that is the fader range), a Toggle, a Menu, a colour, a Pulse (a button: one shot) or a Momentary (a button you hold).
  3. Use the pars inside your network with expressions like parent().par.Speed. Leave the pars themselves plain values: a par with an expression on it cannot be played (Core lists it in core/problems).
  4. Pars on a page called Setup (resolution, file names...) stay private.
  5. They now appear as user.my_look.Speed, user.my_look.Flash ...: MIDI window ▸ Learn ▸ move a knob ▸ pick it. Two COMPs with the same name: only the first works, rename the other. Renaming later = re-learn its MIDI links.

Developer detail: dev/COOKBOOK.md §7b.

Sources (Core's own signals; hidden in the beta)

Core makes signals you can use to move things: four LFOs, a beat and a bar ramp, pulses every 2 / 4 / 8 / 16 beats and two random values (new one every N beats). They follow Core's clock (tap, tempo x2 / half, Ableton Link) exactly. Set them on Core's custom page Sources (LFO shape, rate in beats per cycle, phase offset; random: every N beats, smoothing). They are listed in Core's table sources (core.lfo.1, core.beat, core.every.4, core.rand.1 ...). Linking a source to a parameter in the page is not built (after the artists' feedback). You can already read them in TD: add a Select CHOP with CHOPs = core/sources_gen/out and Channel names = lfo1 (or lfo*), and export / reference the channel on any parameter of your own network, e.g. op('lfo_sel')['lfo1']. They cost nothing until something reads them.
